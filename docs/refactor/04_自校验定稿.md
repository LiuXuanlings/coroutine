## 三、关键需求覆盖校验

### 3.1 单一主干

- [x] SensorSource 是唯一外部输入进程，使用 time::Rate，不引入 Timer（MC-616 已完成）。
- [x] 六类业务 Protobuf 的字段 1/2 已固定为源序列和单调时间，生成类型满足 Channel 边界（MC-614）。
- [x] Perception、Fusion、Planning、Control、ControlAudit 属于同一个业务 `.so` 和同一 DAG（MC-615）。
- [x] ControlSink 是唯一外部结果/指标进程（MC-616 已完成）。
- [ ] INTRA、SHM、AllLatest、协程唤醒、mainboard 和双 Scheduler 均在同一业务链中验证（MC-618/619 待验收）。
- [x] 旧 talker/listener/benchmark 不作为补充 Demo 保留。

### 3.2 CyberRT 忠实度

- [x] Classic 改回调度组共享多级优先级队列，删除工作窃取口径（MC-610 已完成）。
- [x] Choreography 保留定向 Processor 与 Classic 公共池（MC-611 已完成）。
- [x] Component 使用 DataVisitor + RoutineFactory + Scheduler，不在 Reader 发布线程同步 Proc（MC-612 已完成）。
- [x] HybridTransport 按对端关系维护连接，可同时使用 INTRA/SHM（MC-607 已验证）。
- [x] ChannelManager 通过 FastRTPS Participant 传播 Join/Leave，不自创发现协议。
- [x] DAG 与 Scheduler 配置分离（MC-613 已由 mainboard 先解析独立 Scheduler 配置再加载唯一 DAG）。
- [x] 删除 Timer 是范围裁剪，不以 CRoutine::Sleep 自创替代 TimingWheel。

### 3.3 工程边界

- [x] Channel 公开类型限定为 Protobuf Message（MC-607 Hybrid 与 MC-608 Node API 已完成）。
- [x] INTRA 保留 shared_ptr 对象身份；SHM 使用序列化字节（MC-607 已验证）。
- [x] FastRTPS 作为系统依赖，不复制、不自动下载。
- [x] RTPS 数据面类型未进入 MC-606 构建和公开 API。
- [x] CMake 最终使用显式生产源列表。
- [x] 平台限制写入路线图、架构矩阵和验收文档。

### 3.4 测试与性能

- [x] 高风险单测按最终边界收敛（MC-617 已验收）。
- [ ] Classic/Choreography 使用同一 DAG 和同一负载（MC-618/619 待验收）。
- [ ] 默认验收为 1000 条、100 Hz，并包含 AllLatest 次通道预热（MC-618/619 待验收）。
- [ ] 性能只测完整主干，运行时开关控制指标（MC-620 待验收）。
- [ ] 指标为 p50/p95/p99、吞吐、丢包和审计一致性（MC-620 待验收）。
- [x] 旧性能数据不进入新结论。
- [ ] 100% 留存生产文件业务触达（定义已定稿，MC-619 待验收）。

### 3.5 MC-606 质量修正校验

- [x] `ChannelManager` 已成为 Writer/Reader/Node 状态唯一所有者。
- [x] 拓扑控制 Topic 已使用原生 Reliable、Transient Local、Keep All(depth=10) QoS。
- [x] Protobuf 保留字段和枚举已恢复原生编号。
- [x] 本地 Join/Leave 的 FastRTPS 回环已过滤，ChangeListener 精确通知一次。
- [x] 跨进程测试使用管道事件编排双向 Join、DIFF_PROC 与显式 Leave，不使用固定 sleep。
- [x] 发现、SHM、调度和 Component 的高风险覆盖已由 MC-617 收口。

### 3.6 MC-607 至 MC-609 质量评估修正

- [x] Hybrid 同步 INTRA 分发和后端 Disable 已移出状态锁，回调内关闭收发端不再自死锁。
- [x] 正式 Protobuf SHM 两端统一默认段布局，超过 1 KiB 动态字段和较小既存段拒绝已有回归。
- [x] 旧固定 INTRA、非 Protobuf Transport 公开工厂及其孤立测试已删除。
- [x] Classic 优先级测试先建立完整候选集再启动 Processor，不再把入队时序误判为策略错误。
- [x] ConditionNotifier 固定 key 的测试启动窗口已由 MC-617 以有界条件收口，首次失败已登记。
- [x] Component 旧同步路径和阶段注释已由 MC-612 清理；单/双输入 Proc 只在 Processor 协程执行。

### 3.7 MC-610 至 MC-613 质量评估修正

- [x] mainboard 在 Scheduler 线程创建前通过 `pthread_sigmask` 阻塞 SIGINT/SIGTERM，并由主线程使用 `sigwait` 同步消费，初始化期间的单次信号不再丢失。
- [x] RoutineFactory 任务号发布前的数据通知已挂账补唤醒，不把高频后续消息当作正确性保障。
- [x] CPU 亲和性设置结果可观测，绑核测试保持目标线程存活至读回完成。
- [x] `CloseIsIdempotent` 完成精确 SHM 名称的测试自清理，全量 CTest 后无新增 `/dev/shm/minicyber_*` 残留。
- [x] Component 文本 Protobuf 配置不再是 Stub，主干所有权、调度路由与历史 Step/Phase 注释已对齐当前实现。

### 3.8 MC-614 至 MC-616 质量评估修正

- [x] metrics 关闭时不再保存延迟样本，丢包、重复和乱序使用独立统计语义。
- [x] ControlSink 同时观察 Control 与 Audit 集合，启动 ready 条件覆盖最后的 Audit Writer Join。
- [x] 唯一 DAG 的业务队列深度覆盖默认 1000 条验收窗口，不改变 CacheBuffer 落后快进的原生语义。
- [x] 正常成功路径在兜底删除前检查 POSIX SHM 自然回收；失败路径仍只清理四个精确频道。
- [x] 自动驾驶模板实例已移入常驻 `minicyber_autodrive_runtime` 业务库，通用核心库不再编译具体业务消息。

## 四、已解决的口径冲突

| 旧口径 | 新定稿口径 | 处理 |
|---|---|---|
| Demo 必须包含 TimerComponent | 删除 TimerComponent；SensorSource 用 Rate 控制输入节拍 | 新用户决策覆盖旧要求。 |
| Classic 是工作窃取/每 Processor 本地队列 | 同组 Processor 共享 20 级队列，Acquire 防重复执行 | MC-610 重构并全仓删除旧表述。 |
| Transport 自动固定 INTRA、SHM 显式调用 | ChannelManager 动态发现，Hybrid 按对端 INTRA/SHM 扇出 | MC-606~608 重构。 |
| RTPS 完全不出现 | FastRTPS 仅保留 Channel 发现控制面，数据面仍禁止 | 控制面/数据面边界明确。 |
| SHM 可直接传任意模板对象 | Channel API Protobuf-only，SHM 传序列化字节 | MC-607/608 重构。 |
| Component 同步回调 Proc | DataVisitor/RoutineFactory/Scheduler 协程执行 | MC-609/612 重构。 |
| 保留 1~4 输入 Component | 只保留单/双输入 | MC-609/612 清理。 |
| 多个示例与独立 benchmark | 唯一自动驾驶主干兼做功能与性能入口 | MC-603、MC-614~620。 |
| 两份 DAG 展示两种 Scheduler | 同一 DAG 配两份 Scheduler 配置 | MC-613/615。 |
