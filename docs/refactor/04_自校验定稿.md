## 三、关键需求覆盖校验

### 3.1 单一主干

- [x] SensorSource 是唯一外部输入进程，使用 time::Rate，不引入 Timer。
- [x] Perception、Fusion、Planning、Control、ControlAudit 属于同一个业务 `.so` 和同一 DAG。
- [x] ControlSink 是唯一外部结果/指标进程。
- [x] INTRA、SHM、AllLatest、协程唤醒、mainboard 和双 Scheduler 均在同一业务链中验证。
- [x] 旧 talker/listener/benchmark 不作为补充 Demo 保留。

### 3.2 CyberRT 忠实度

- [x] Classic 改回调度组共享多级优先级队列，删除工作窃取口径。
- [x] Choreography 保留定向 Processor 与 Classic 公共池。
- [x] Component 使用 DataVisitor + RoutineFactory + Scheduler，不在 Reader 发布线程同步 Proc。
- [x] HybridTransport 按对端关系维护连接，可同时使用 INTRA/SHM。
- [x] ChannelManager 通过 FastRTPS Participant 传播 Join/Leave，不自创发现协议。
- [x] DAG 与 Scheduler 配置分离。
- [x] 删除 Timer 是范围裁剪，不以 CRoutine::Sleep 自创替代 TimingWheel。

### 3.3 工程边界

- [x] Channel 公开类型限定为 Protobuf Message。
- [x] INTRA 保留 shared_ptr 对象身份；SHM 使用序列化字节。
- [x] FastRTPS 作为系统依赖，不复制、不自动下载。
- [x] RTPS 数据面类型禁止构建和暴露。
- [x] CMake 最终使用显式生产源列表。
- [x] 平台限制写入路线图、架构矩阵和验收文档。

### 3.4 测试与性能

- [x] 高风险单测边界明确，不追求旧测试数量。
- [x] Classic/Choreography 使用同一 DAG 和同一负载。
- [x] 默认验收为 1000 条、100 Hz，并包含 AllLatest 次通道预热。
- [x] 性能只测完整主干，运行时开关控制指标。
- [x] 指标为 p50/p95/p99、吞吐、丢包和审计一致性。
- [x] 旧性能数据不进入新结论。
- [x] 100% 覆盖定义为留存生产文件业务触达，不是 100% 行/分支覆盖。

## 四、已解决的口径冲突

| 旧口径 | 新定稿口径 | 处理 |
|---|---|---|
| Demo 必须包含 TimerComponent | 删除 TimerComponent；SensorSource 用 Rate 控制输入节拍 | 新用户决策覆盖旧要求。 |
| Classic 是工作窃取/每 Processor 本地队列 | 同组 Processor 共享 20 级队列，Acquire 防重复执行 | MC-610 重构并全仓删除旧表述。 |
| Transport 自动固定 INTRA、SHM 显式调用 | ChannelManager 动态发现，Hybrid 按对端 INTRA/SHM 扇出 | MC-606~608 重构。 |
| RTPS 完全不出现 | FastRTPS 仅保留 Channel 发现控制面，数据面仍禁止 | 控制面/数据面边界明确。 |
| SHM 可直接传任意模板对象 | Channel API Protobuf-only，SHM 传序列化字节 | MC-607/608 重构。 |
| Component 同步回调 Proc | DataVisitor/RoutineFactory/Scheduler 协程执行 | MC-609/612 重构。 |
| 保留 1~4 输入 Component | 只保留单/双输入 | MC-609/612 清理。 |
| 多个示例与独立 benchmark | 唯一自动驾驶主干兼做功能与性能入口 | MC-603、MC-614~620。 |
| 两份 DAG 展示两种 Scheduler | 同一 DAG 配两份 Scheduler 配置 | MC-613/615。 |
