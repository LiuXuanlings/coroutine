# MiniCyber 第二次重构实施方案

> 本文是 MC-601 及后续任务的唯一执行方案。任务状态、Commit Hash 和验证结果只记录在 `docs/refactor/00_进度记录.md`。执行任何任务前，必须先读取根目录 `AGENTS.md`、`MINICYBER_ROADMAP.md`、进度台账和当前任务卡列出的原生参考文件。

## 一、前置总览

### 1.1 重构目标

本轮重构不再增加离散示例，而是围绕一条真实自动驾驶业务流水线收拢全部保留能力：

```text
SensorSource 独立进程
  -> CameraFrame、VehicleState（跨进程 SHM）
  -> PerceptionComponent<CameraFrame>
  -> PerceptionObstacle（同进程 INTRA）
  -> FusionComponent<PerceptionObstacle, VehicleState>（AllLatest）
  -> FusedObstacle（同进程 INTRA）
  -> PlanningComponent<FusedObstacle>
  -> Trajectory（同进程 INTRA）
  -> ControlComponent<Trajectory>
  -> ControlCommand
       -> ControlAuditComponent（同进程 INTRA）
       -> ControlSink 独立进程（跨进程 SHM）
```

唯一主干必须同时穿透：mainboard、`.dag`、`.so` 动态加载、ComponentFactory、单/双通道 Component、AllLatest、DataVisitor、DataNotifier、Scheduler、CRoutine、INTRA、SHM、HybridTransport、ChannelManager、FastRTPS 拓扑发现控制面、Node/Reader/Writer、Protobuf 序列化、time::Rate 和优雅退出。

### 1.2 已确认决策清单

1. 文档除代码、CMake 指令和英文专有名词外全部使用中文。
2. 仅支持 `Linux x86_64 + C++17 + POSIX SHM`。
3. 核心范围为 `mainboard/component/node/transport/data/scheduler/croutine/topology/service_discovery/time/base`；`service_discovery` 只保留 Channel 发现子集。
4. 彻底删除 RPC `service/client`、Timer/TimerComponent、旧示例、旧性能程序、旧性能数据和离散学习文档。
5. TimerComponent 的删除决策覆盖最初“Demo 必须包含 TimerComponent”的旧验收项。数据源由独立 SensorSource 使用原生职责一致的 `time::Rate` 控制回放频率。
6. 所有公开 Channel API 只接受 `google::protobuf::Message` 派生类型。
7. INTRA 在同进程传递同一个 `shared_ptr`，不得序列化或复制消息对象；SHM 写入 Protobuf 序列化字节，接收端反序列化为新对象。
8. FastRTPS 是系统前置依赖，通过 `find_package(FastRTPS REQUIRED)` 查找；仅用于同机 Channel Join/Leave 控制面，禁止 RTPS 数据面。
9. HybridTransport 按每个对端的进程关系并行扇出：本进程 Reader 使用 INTRA，其他进程 Reader 使用 SHM；两类 Reader 可同时存在。
10. Writer 在 ChannelManager 确认 Reader Join 后发布，不使用固定睡眠猜测拓扑是否就绪。
11. Component 只保留单通道和双通道特化；双通道由首通道驱动 AllLatest，复用第二通道最新值。
12. Component 禁止在发布线程同步调用 Proc；执行链必须为 `DataNotifier -> Scheduler::NotifyTask -> DATA_WAIT/READY -> Processor -> CRoutine::Resume -> Proc`。
13. Classic 正式定义为“调度组共享多级优先级队列”。禁止“工作窃取”表述和跨组窃取代码；`Acquire()` 仅防止协程被并发重复执行。
14. Choreography 保留原生双区：显式指定 processor 的任务进入定向 Processor，未指定任务进入 Classic 公共池。
15. 同一份业务 DAG 分别搭配 Classic 和 Choreography 两份 Scheduler Protobuf 配置，不复制业务 DAG。
16. 业务组件必须编译为 `.so`，由 ModuleController 使用 `dlopen(RTLD_NOW | RTLD_GLOBAL)` 加载，再由 ComponentFactory 创建。
17. 主验收负载为 `--messages 1000 --frequency 100`，约运行 10 秒；Classic 和 Choreography 各完整运行一次。
18. 指标由唯一主干的运行时开关启用，统计 p50/p95/p99、吞吐和丢包，输出 CSV/JSON；不保留旧基准和旧数据。
19. “100% 核心文件覆盖”指每个留存生产代码文件均进入主干的静态调用链或运行时加载链，并由集成测试证明文件级触达；不要求全部异常分支或 100% 行覆盖。
20. 高风险单元测试只保留 CRoutine ABI、SHM 崩溃信号清理、Protobuf 序列化和调度策略等必要集合；完整流水线集成测试是主验收。
21. 单任务单 Commit，统一提交并推送到 `development`，严禁提交或推送到 `main`。
22. 每开始一个任务先在 `00_进度记录.md` 标为“进行中”；完成后填写真实 Commit Hash、验证命令和结果，再标为“已完成”。
23. 永久维护 `MINICYBER_ROADMAP.md` 与 `docs/refactor/00_进度记录.md` 至 `05_实施归档.md` 的联动基线；后续架构或验收变更必须同步检查七份基线文件，不得删除 02~05 或建立第二套事实源。
24. Protobuf 保留字段和枚举必须沿用原生编号；裁剪字段使用 `reserved` 或保留原编号空位，
    不得为了连续或美观重新编号。
25. Channel 发现职责固定分层为 `TopologyManager -> ChannelManager -> Participant/ChangeSignal`：
    ChannelManager 是角色状态唯一所有者，TopologyManager 只编排控制通信和监听生命周期。
26. 拓扑控制 Topic 使用原生 `Reliable + Transient Local + Keep All(depth=10)` QoS；过滤
    本进程 FastRTPS 回环，使每次本地 Join/Leave 对监听器精确通知一次。
27. 生产代码任务必须同步补充关键意图注释和 `INTERVIEW_QA.md` 增量；重大排错必须在
    同一任务将完整排查时间线写入 `DEBUG_MANUAL.md`，不得推迟到最终文档任务。
28. 每个任务收口时必须同步路线图、00、04、05，并检查 01/02/03；00 中的完成证据使用
    完整 40 位 Commit SHA、subject、实际验证和远端同步状态。

### 1.4 黑名单

以下能力和文件不得在最终代码库继续存在：

- `include/minicyber/service/**`、RPC Client/Service 实现及测试。
- `include/minicyber/component/timer_component.h`、TimerComponentConfig、DAG timer_components 字段及测试。
- `examples/talker.cpp`、`examples/listener.cpp`、旧 benchmark、C++20 coroutine 探针和 PIPE/互斥队列对照程序。
- `scripts/collect_benchmark.sh`、旧 CSV/JSON、旧英文性能报告。
- `RtpsTransmitter`、`RtpsReceiver`、`RtpsDispatcher`、Hybrid 的 DIFF_HOST 数据路径以及任何公开 RTPS 数据模式。
- Component 的零输入、三输入、四输入特化，以及对应 DataVisitor/RoutineFactory 的未使用三/四输入路径。
- 普通 C++ 对象直接跨 SHM 复制的接口。
- Classic 跨组窃取、每个 Processor 私有 `proc_i` 调度组等非原生语义。
- 无法进入唯一主干调用链、且不属于明确高风险测试支撑的生产文件。
- 基线文档组之外的旧离散学习笔记、过期归档和旧性能数据；有价值的事实必须先迁入新手册。当前 00~05 文档不得删除。

### 1.5 全阶段共同门禁

- 每个任务只能修改任务卡声明范围内的文件；发现额外问题先登记，不得顺手扩张。

- 开始编码前必须形成“原生职责映射检查”：逐项列出本任务新增/修改的类、协议和生命
  周期分别对应哪个 `cyber_ref` 文件。任务卡点名的原生职责类若不存在，不得用功能近似
  的自定义类冒充；必须补齐原生分层或登记冲突。
- 公开 API、协议编号、并发状态机、所有权、失败回滚和关闭顺序必须写意图注释，说明
  关键不变量与原生职责；不要求逐行注释显而易见的赋值和分支。
- 每个生产代码任务必须增量更新 `docs/INTERVIEW_QA.md`。涉及重大 Bug、泄漏、死锁、
  ABI、生命周期或选型时，同一任务必须更新 `docs/DEBUG_MANUAL.md`；调试条目必须包含
  复现、原始现象、排查时间线、候选假设、工具命令、关键输出、根因、修复和回归。
- 删除知识文档前必须在任务记录中提供逐文件迁移表，逐项写明“迁入目标章节”或
  “删除原因”；禁止用“已迁移”概括一批文件。
- 每个任务结束同步路线图、00、04、05 的指针和产物状态；01/02/03 逐份检查后在 00
  记录“已修改”或“不适用及原因”。
- 关键单元测试和主干集成测试通过即可；不得恢复庞大、低价值、纯实现细节测试矩阵。
- 任何阶段门禁失败时，在进度台账标记“阻塞”，保留证据并停止进入下一任务。

## 五、风险与待关注项

1. **FastRTPS CMake 包名风险**：用户确认使用 `find_package(FastRTPS REQUIRED)`，但不同发行版可能导出 `fastrtps` 或 Fast DDS 名称。MC-604 必须记录目标环境的真实 Config Package 和链接 target；不得用 FetchContent 或复制源码绕过系统依赖决策。
2. **控制面裁剪风险**：原生 TopologyManager 同时含 Node/Channel/Service，Participant 也位于 transport/rtps。裁剪时必须保留 Channel Join/Leave 所需依赖，同时以构建和符号扫描证明 RTPS 数据面没有混入。
3. **发现收敛与启动竞态**：FastRTPS Join/Leave 是异步的。Demo 必须依赖 HasReader/拓扑条件和有界超时，不能用固定 sleep；超时日志必须输出缺少的 Channel/Role。
4. **混合扇出重复投递风险**：HybridReceiver 同时启用 INTRA/SHM 时必须按具体对端关系启用连接，不能让本进程同一消息从两种后端重复到达。
5. **Protobuf 动态库 ABI 风险**：mainboard、核心库和组件 `.so` 必须链接同一 Protobuf ABI 与同一个 ComponentFactory 实例；需要真实 dlopen 测试覆盖注册、创建、Shutdown、dlclose 顺序。
6. **SHM 容量与反序列化风险**：序列化大小必须在申请块前确定；超限、解析失败、序列不匹配必须可诊断并正确释放块引用。
7. **协程丢失唤醒风险**：AllLatest 填充回调必须先于 Scheduler 唤醒回调注册；CRoutine 设置 DATA_WAIT、TryFetch 和 Yield 的顺序必须对照原生 RoutineFactory，并用重复测试验证。
8. **Classic 静态组生命周期风险**：多个测试或 Scheduler 顺序创建时，共享组静态状态必须在 Shutdown 清理，不能残留 stop 标记或旧协程。
9. **Choreography 配置越界风险**：processor_id、定向区数量、公共池数量和 cpuset 必须启动前校验；非法配置应拒绝启动，不得静默轮询降级。
10. **性能扰动风险**：metrics 关闭时不得维护分位数样本；开启时统一使用跨进程可比较的单调时钟和源序列，报告必须注明统计开销。
11. **10 秒测试波动风险**：默认业务验收固定 1000 条/100 Hz；高负载性能采集另用参数扩大样本，不得把短验收数据包装成稳定性能结论。
