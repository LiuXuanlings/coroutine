# MiniCyber 可执行重构方案

## 1. 使用方式

本方案以最小任务为执行单位，禁止直接执行整个阶段。每次会话只推进一个任务卡；任务过大时必须先拆分，再开始代码改动。

执行指令示例：`执行 MC-001`、`继续当前未完成任务`。开始前，执行者必须先读 `00_进度记录.md`，再读任务卡列出的原生参考文件和当前 MiniCyber 对应文件。完成后必须更新进度记录、执行最小验证并创建一个只包含该任务的 commit。

新会话接力指令：`读取 MINICYBER_ROADMAP.md 和 docs/refactor/00_进度记录.md，从当前任务继续；不得跳过任务或合并提交。`

## 2. 全局约束

- 唯一架构依据：`cyber_ref` 当前源码；存在偏差时对齐或删除。
- 首期范围：CRoutine/Scheduler（Classic、Choreography）、Node/Reader/Writer、INTRA、SHM、Component/DAG/mainboard。
- 不实现：RTPS、跨机通信、监控运维、参数服务、录包回放、Python。
- 每一个任务卡对应一个原子 commit；仅修复该任务引入的构建问题可随同提交，其他问题另建任务。
- 未经明确指令，不跨任务修改代码；遇到设计不确定、原生行为与现有接口冲突时，在进度记录标为“阻塞”并提问。

## 3. 任务卡

状态以 `00_进度记录.md` 为准。每张任务卡都必须产出：代码或文档变更、最小验证命令/结果、单一 commit。

## 4. 阶段门禁

阶段 A 完成才可进入 B；B 完成才可进入 C；C 完成才可进入 D；D 完成才可进入 E；E 完成才可进入 F。每个阶段门禁为：该阶段任务全部完成、关联最小测试通过、进度记录更新、所有任务均存在单一 commit。
