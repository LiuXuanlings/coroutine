# 实施归档

本文件是完成重构后的导航页。对当前实现状态，以
[`00_进度记录.md`](00_进度记录.md) 为事实来源；对首期范围，以
[`02_架构取舍矩阵.md`](02_架构取舍矩阵.md) 为准；对性能结论，以
[`perf/performance_report.md`](perf/performance_report.md) 和其原始数据为准。
早期设计笔记用于保留推导过程，不作为当前行为声明。

## 架构边界

| 模块 | 已交付的边界 | 主要证据 |
|---|---|---|
| CRoutine | x86_64 栈式上下文、状态机和生命周期 | `test_croutine`、`test_processor_context` |
| Scheduler | Classic 多级优先级本地队列与 Choreography 定向路由 | `test_scheduler_classic`、`test_scheduler_choreography` |
| Data | Cache/Channel buffer、分发、通知、AllLatest 融合 | data 相关单元测试 |
| Transport | 自动工厂仅 INTRA；SHM 是显式收发器 API | `test_transport_routing`、SHM 跨进程测试 |
| Node | Reader/Writer、默认有界历史、端点显式关闭 | `test_node` |
| Component/mainboard | Component、TimerComponent、DAG 校验、失败回滚 | component/module controller 测试 |

明确不在首期：RTPS/跨机、监控运维、参数服务、record、Python API。标准库
C++20 coroutine 仅有独立编译/恢复探针，不是调度或传输性能基线。

## 已解决问题

| 问题 | 处理与证据 |
|---|---|
| 汇编构建定义错误 | 通过 C 编译器驱动预处理汇编；后续 Debug/Release 构建成功。 |
| GoogleTest 镜像不可用 | 支持 `FETCHCONTENT_SOURCE_DIR_GOOGLETEST` 本地覆盖；复现命令均记录该参数。 |
| 自动 SHM 路由会因端点创建顺序分流 | 自动 `Transport` 固定 INTRA，跨进程调用方显式使用 SHM 收发器。 |
| 端点、回调和组件失败路径可能留下资源 | 增加显式注销、in-flight 同步、幂等关闭和加载水位回滚测试。 |
| 性能口径不可比 | 统一为 SPSC 单向、相同帧大小、预热和样本字段；每条消息限制一个在途。 |
| SHM 基准子进程会遗留段 | 接收子进程写回结果前显式关闭 `ShmDispatcher`；基准前后目录比对无新增段。 |

## 已知限制

- 上下文切换实现和测试覆盖 x86_64；未提供 aarch64 汇编实现。
- 当前宿主运行 TSAN 会在测试开始前报 `unexpected memory mapping`；配置与编译已验证，需在支持 TSAN 的宿主复验。
- SHM notifier 使用轮询，性能报告中的 SHM 分位数包含该通知策略和接收端复制成本。
- 性能报告是单机单次样本集合，未控制 CPU 亲和性或系统负载，也未提供置信区间。
- README 中的 `talker`/`listener` 是 API 示例，不构成自动跨进程通信演示。
