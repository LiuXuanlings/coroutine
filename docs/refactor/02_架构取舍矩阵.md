# MiniCyber 第二次重构架构取舍矩阵

> 本文件只记录已经由用户确认的架构决策，是 MC-601~MC-623 的选型事实源。任务执行者可以在该边界内实现和验证，不得重新选择技术路线或加入“更优”的自创替代方案。

## 一、取舍原则

1. 原生 CyberRT 职责一致性优先于代码复用和局部性能。
2. 可以删除非核心能力，但保留能力的数据流、类依赖和生命周期必须与原生设计一致。
3. 所有保留的生产文件必须进入唯一自动驾驶主干的静态调用链或运行时加载链。
4. 同一个架构事实只能有一个真相源。例如 Channel 拓扑统一由 service_discovery/ChannelManager 管理，不再保留第二套本地拓扑表。
5. 项目定位是 C++17 高性能中间件实践，不扩张为自动驾驶算法、运维平台或通用 RPC 框架。

## 二、总体范围矩阵

| 能力 | 最终决策 | 原生参考 | 实施任务 | 禁止偏移 |
|---|---|---|---|---|
| 平台 | 仅 Linux x86_64、C++17、POSIX SHM | `cyber/croutine/detail/swap_x86_64.S`、`cyber/transport/shm` | MC-604、MC-623 | 不宣传 aarch64、Windows 或跨主机数据能力。 |
| CRoutine | 保留栈式协程、状态机和 x86_64 SwapContext | `cyber/croutine` | MC-609、MC-617 | 不替换为 C++20 stackless coroutine。 |
| Scheduler | 保留 Classic 与 Choreography | `cyber/scheduler` | MC-610、MC-611 | 不新增第三种策略。 |
| Data | 保留 Dispatcher、Notifier、Visitor、单/双通道 AllLatest | `cyber/data` | MC-609 | 删除未使用三/四输入路径，不新增自定义融合策略。 |
| Transport | 只保留 INTRA、SHM 和二者的 Hybrid | `cyber/transport` | MC-607 | 禁止 RTPS 数据面和固定创建时一次性路由。 |
| Discovery | 保留 FastRTPS Participant + ChannelManager 最小控制面 | `cyber/service_discovery` | MC-606 | 不保留 ServiceManager；不使用自研 Socket/文件注册中心。 |
| Node | 保留 Protobuf-only Reader/Writer、HasReader 和端点生命周期 | `cyber/node` | MC-608 | 不允许普通 C++ 对象 Channel；不在 Reader 同步执行 Component::Proc。 |
| Component | 只保留单通道、双通道和 ComponentBase/Factory | `cyber/component/component.h` | MC-612 | 删除零输入、三输入、四输入和 TimerComponent。 |
| Mainboard | 保留同一 DAG、独立调度配置、强制 `.so + dlopen` | `cyber/mainboard` | MC-613 | 生产路径禁止空 module_library 和静态注册绕过。 |
| Time | 保留 Time、Duration、Rate | `cyber/time` | MC-605 | 不引入 TimingWheel 或伪 Timer。 |
| RPC | 彻底删除 service/client | `cyber/service` 仅作删除边界参考 | MC-603 | 不以 Channel 包装自研 RPC。 |
| Demo | 只保留唯一自动驾驶主干 | 本项目业务层 | MC-614~MC-616 | 删除 talker/listener、ping-pong 和零散子 Demo。 |
| 性能 | 指标内置于唯一主干，通过运行时开关启用 | 本项目验收层 | MC-616、MC-620 | 删除旧 benchmark、PIPE、互斥队列、C++20 对照和旧数据。 |

## 三、调度与协程决策

| 决策点 | 定稿行为 | 设计依据 | 验收证据 |
|---|---|---|---|
| Classic 名称 | “调度组共享多级优先级队列” | 原生同组 Processor 共享 `MULTI_PRIO_QUEUE` | Classic 配置运行及共享组单测。 |
| Classic 队列 | 每个 group 一组 20 级共享队列，同组 Processor 从高到低扫描 | `classic_context.{h,cc}` | 不存在 per-processor `proc_i` 私有组。 |
| Acquire | 只防止同一 CRoutine 被多个 Processor 并发执行 | `CRoutine::Acquire/Release` | 竞争测试证明无重复执行。 |
| 工作窃取 | 概念、代码、注释和宣传全部删除 | 原生 Classic 无跨组窃取 | 全仓 `work-stealing/工作窃取/Steal` 语义扫描为零。 |
| 数据等待 | RoutineFactory 每轮设置 DATA_WAIT，TryFetch 成功后 Proc 并 Yield READY | `cyber/croutine/routine_factory.h` | 集成日志或探针显示 DATA_WAIT -> READY -> Resume。 |
| 数据唤醒 | DataVisitor notifier 回调 Scheduler::NotifyTask，设置更新标记并唤醒原路由 | `scheduler.cc`、`data_visitor_base.h` | 发布线程不直接调用 Proc。 |
| Choreography | 显式 processor_id 任务进入定向区 | `scheduler_choreography.cc` | 配置指定组件只在目标 Processor 执行。 |
| Choreography 公共池 | 未配置 processor 的任务进入 Classic 默认共享池 | 原生双区结构 | 同一次主干运行同时触达定向区和公共池。 |
| 策略选择 | 同一份 DAG 配两份 Scheduler Protobuf 配置 | 原生 DAG 与 Scheduler 配置职责分离 | Classic/Choreography 两次运行使用相同 DAG Hash。 |

## 四、数据、Component 与业务执行决策

| 决策点 | 定稿行为 | 设计依据 | 验收证据 |
|---|---|---|---|
| Channel 类型 | 公开 API 仅接受 `google::protobuf::Message` 派生类型 | 统一跨进程序列化边界 | 非 Protobuf 类型编译期拒绝。 |
| 单通道 Component | Reader 只向 DataDispatcher 填充数据；RoutineFactory 在协程中调用 Proc | 原生 reality mode | Proc 线程为 Processor，不是发布线程。 |
| 双通道 Component | 第一个 Reader 是主驱动；第二个 Reader 提供最新值 | 原生 AllLatest | 次通道无值时不融合；预热后输出完整测量序列。 |
| AllLatest | 主通道每次到达尝试融合，复用次通道最新值 | `cyber/data/fusion/all_latest.h` | 不宣传时间戳严格对齐或 Barrier。 |
| 支持通道数 | Component/DataVisitor/RoutineFactory 只保留一、二输入 | 唯一主干只需要这两种职责 | 三/四输入代码和测试物理删除。 |
| Timer | Timer、TimingWheel、TimerComponent、配置字段全部删除 | 非核心且完整原生实现会引入额外线程/模块 | 全仓无 TimerComponent 生产入口。 |
| 输入节拍 | SensorSource 独立进程使用 time::Rate | 传感器驱动/回放节拍不属于 Component 调度 | 100 Hz、1000 条约 10 秒。 |
| 业务算法 | 纯 C++ 确定性字段变换与简单数学 | 突出中间件而非算法库 | 同一输入产生可断言的控制输出。 |
| 动态组件 | 五个业务组件编译进同一个共享库 | 原生 mainboard + class loader 职责 | ModuleController 真实 dlopen 并反射创建。 |

## 五、发现与传输决策

| 决策点 | 定稿行为 | 设计依据 | 验收证据 |
|---|---|---|---|
| 控制面依赖 | 系统 FastRTPS，CMake `find_package(FastRTPS REQUIRED)` | 原生 service_discovery 使用 Participant 广播 Join/Leave | 两个同机进程互相发现端点。 |
| FastRTPS 范围 | 只编译 Participant、监听器、Channel Join/Leave | 控制面/数据面隔离 | 构建和符号表无 RtpsTransmitter/Receiver/Dispatcher。 |
| 同机限制 | 只接受同主机 Channel 角色关系 | 数据面只实现 INTRA/SHM | DIFF_HOST 不创建数据连接。 |
| 拓扑真相源 | TopologyManager 内只保留 ChannelManager 子集 | 原生具体管理器模型 | 不存在旧 `IsSameProc` 静态本地表并行维护。 |
| 就绪门禁 | Writer::HasReader 查询 ChannelManager | 原生 Writer 拓扑查询职责 | 数据源不靠固定 sleep 猜测启动。 |
| INTRA | 同进程传递同一个 `shared_ptr` | 原生 IntraDispatcher | 指针身份和路由计数证明零对象复制。 |
| SHM | Protobuf 序列化字节写入 POSIX SHM，接收端反序列化 | 跨进程不能共享 C++ 动态对象 | 动态字段消息跨进程正确恢复。 |
| Hybrid | 按每个对端 RoleAttributes 启停 INTRA/SHM 连接 | 原生 HybridTransmitter/Receiver | 一个 ControlCommand Writer 同时送达本地 Audit 与外部 Sink。 |
| 混合扇出 | 本进程 Reader 走 INTRA，其他进程 Reader 走 SHM，两者并存 | 原生 per-opposite connection | 不允许全局二选一或创建时固定模式。 |
| 跨主机 | 不支持 RTPS 数据传输 | 明确项目边界 | README、公开 API、构建产物均不出现该能力。 |

## 六、运行时、构建与插件决策

| 决策点 | 定稿行为 | 设计依据 | 验收证据 |
|---|---|---|---|
| DAG | 唯一 `config/autodrive/autodrive.dag` | 单一业务主干 | 两种策略复用同一文件。 |
| Scheduler 配置 | 精简且字段职责对齐原生 `scheduler_conf.proto` | 策略不属于 DAG | mainboard 通过独立参数加载。 |
| module_library | 生产 DAG 必须非空 | 强制真实插件边界 | 空路径在生产验收中被拒绝。 |
| 动态加载 | `dlopen(RTLD_NOW | RTLD_GLOBAL)` 后由 ComponentFactory 创建 | 原生 class loader 职责的精简实现 | `.so` 静态注册、创建、关闭、dlclose 顺序测试。 |
| 构建源列表 | CMake 显式列出生产源和目标 | 防止黑名单文件被 GLOB 重新编译 | 构建清单与文件触达清单一一对应。 |
| FastRTPS 获取 | 仅系统前置依赖，不复制源码、不自动下载镜像 | 用户明确决策 | 缺失时配置明确失败并给出安装提示。 |
| Sanitizer | 保留 Debug/Release/ASAN/TSAN 预设 | 风险适配 | ASAN 跑关键链；TSAN 宿主失败如实记录。 |
| 插件 ABI | mainboard、核心库和业务 `.so` 使用相同 Protobuf ABI 与唯一工厂实例 | 避免 DSO 单例分裂 | 真实 dlopen 集成测试。 |

## 十、允许后续提问的唯一条件

以下情况不允许自行假设，也不属于重复确认：

1. 系统 FastRTPS Config Package 与用户指定 `find_package(FastRTPS REQUIRED)` 在目标发行版不可兼容。
2. `cyber_ref` 原生职责与已确认决策存在无法同时满足的直接证据。
3. 当前任务必须修改下一任务所有权文件才能编译或验证，且无法通过任务拆分解决。
4. 外部环境导致同一阻塞重复出现，并且没有安全的原生替代路径。

其他实现细节由 Agent 对照 `cyber_ref`、当前任务卡和本文自主完成。
